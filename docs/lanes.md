# The three lanes

Once an item is clarified, it goes into exactly one lane. Each lane answers a different question and has its own stores. Data moves between lanes only along one of the seven links I1–I7.

## 1 · Action lane · GTD + PARA

Turns intentions into finished work. GTD handles the chain of decisions (one step or many, do it now, later or hand it off) and the daily loop. PARA draws the boundaries: what has an end (Projects), what must be kept up forever (Areas), and when to file something in the Archive.

- **Core question:** What is the next concrete step?
- **In:** tasks from the Inbox, I2 idea becomes a task, I4 reading prescription, I6 issues assigned to you, I7 corrections, one project per Area each quarter.
- **Out:** finished work, the Archive with a reason recorded, I1 lessons, I3 a new category and board.
- **Project lifecycle:** Someday → Active → Done or Stopped → Archive.

### Rules
1. Record the done criteria and the stop criteria the moment you create a project.
2. A multi-step project has a board in its repository; backlog, milestones, due dates and owners live on the board. See [the execution layer](execution-layer.md).
3. A next action starts with a verb and can be finished in one sitting, at most 90 minutes.
4. A next action that belongs to a project carries `[[project]]` and the issue number if there is one.
5. Waiting For is only for things you wait for from outside any board. Work handed out inside a project gets an owner on its board.
6. No limit on the number of projects or next actions (since 2.2.0).
7. A next action you want the assistant to do gets an assignment label with `brain assign` (since 3.0). See [flow.md](flow.md#the-assistant-loop).

### Measure every week
- Tasks finished, active projects, open next actions.
- Issues opened and closed on each board, late milestones.
- Age of the oldest Inbox item; keep it under 7 days.
- Tasks assigned to the assistant: open, done, stale.

### Warning signs
- An active project with nothing in progress, neither on its board nor in Next Actions.
- Next Actions so long that in the morning you cannot pick a task.
- Someday never gets reviewed and turns into a second junk drawer.
- You do work that is on no list: the system is being bypassed.

## 2 · Knowledge lane · Zettelkasten + LYT + FSRS

Turns what you read and what you do into understanding of your own, then keeps it in memory. Zettelkasten distils it into single-idea notes linked to each other, LYT draws a map once a cluster of notes is dense enough, and FSRS schedules the reviews.

- **Core question:** Which idea I already have does this connect to?
- **In:** ideas from the Inbox, sources you read, I1 lessons, I5 results of test runs.
- **Out:** writing and decisions, I2 idea becomes a task, I4 reading prescription, I7 corrections.
- **Lifecycle of an idea:** Fleeting → Literature → Permanent → part of a map of content → turned into flashcards → remembered, or deleted after 7 days.

### Rules
1. Write in your own words; never copy and paste.
2. A permanent note holds one idea, and its title is a claim.
3. Every new permanent note links to at least one existing note the moment you write it.
4. Create a map of content only when a cluster has about 7 notes.
5. Flashcards come only from permanent notes or knowledge maps, never from raw sources.
6. A knowledge map written by an AI is **reading material**, not your permanent note. Knowledge becomes yours only when you rewrite it yourself.
7. Gates G2–G4 apply at the literature, permanent and flashcard doors. See [the trust gates](trust-gates.md).

### Measure every week
- New permanent notes; about 3 a week is a good start.
- Cards reviewed and retention rate; FSRS aims for about 90% by default.
- Overdue cards; keep them under about 100.

### Warning signs
- Plenty of literature notes and few permanent ones: you are collecting, not thinking.
- Overdue cards pile up into the hundreds.
- Notes with no links: the lane has become a storage bin.
- Reading knowledge maps without writing a single note: the knowledge is still not yours.

## 3 · Files and code lane · Johnny Decimal

Holds everything that is not a note: scripts, prompts, configs, run logs, videos, exports. Johnny Decimal gives each one a fixed numeric address, so a note or a task only needs to say "see 51.03".

- **Core question:** Which number does this live at?
- **In:** files from the Inbox, files generated by tools, I3 a project that needs a home.
- **Out:** a repository with a board, I5 new figures, I6 issues and blocking errors.
- **Lifecycle of a file:** no number → a line in the Index → a folder → in use → closed, number kept.

### Rules
1. Write the line in the Index first, then create the folder.
2. Never reuse a number. Mark a closed category and keep its number.
3. Do not nest folders below the AC.ID level; 51.03 is the last named level.
4. Notes do not live in this lane. A note only cites the number.
5. Each category maps to 1 repository, and that repository has a board if its project has several steps.
6. Area 50–59, at most 10 categories; 10, 20, 30 and 40 are taken by vault folders.

### Measure every week
- Files still outside the system (Downloads, Desktop).
- Whether the Index matches the real folders.
- Categories used out of 10.

### Warning signs
- Files still sit in Downloads.
- A category opened for a project that has no real files yet.
- The Index drifts from the folders: numbers on paper that point nowhere.

The thresholds (7 notes, 3 lapses, 7 days, 90 minutes) are starting points. Adjust them after 4 weeks of measuring; most of them live in `brain.toml` (see [the configuration reference](architecture.md#85-configuration-reference-braintoml)).
